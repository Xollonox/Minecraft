# Minecraft-W / Voxel Sandbox — Version 9 Character & Challenge Release

An original browser voxel-survival engine built with [Three.js](https://threejs.org/), plain ES
modules and Vite. Version 9 combines deterministic infinite terrain and worker-based chunk streaming
with survival stats, crafting, containers, stateful blocks, fluids, fire, mobs, farming, equipment,
projectiles, early redstone and crash-safe saves. Keyboard/mouse, touch and gamepad are first-class.
There is no backend or account requirement; textures and sounds are generated by the project.

Version 9 contains a playable survival campaign: progress through
the Overworld and Nether, locate and fill a stronghold portal, defeat the Ender Dragon, visit outer
End cities, return through the exit portal and see the original poem and credits. It also includes
advancements, statistics, death markers, save migration and the four-crystal dragon respawn ritual.
This release deliberately does not claim exact edition parity or completion of every item in the
122-item aspirational roadmap. See `V9-IMPROVEMENTS.md` for the verified v9 scope.

> **Unofficial.** This project is not affiliated with, endorsed by, or connected to Mojang Studios,
> Microsoft, or *Minecraft* in any way. Every texture, sound, font and interface element is original
> and generated by the code in this repository.

## Features

**World**
- Deterministic seeded generation — the same seed always builds the same world
- Effectively infinite streaming in all four directions, with correct negative coordinates
- Layered terrain shaping: continentalness, erosion, hilliness and ridge noise
- 45 registered surface and cave biomes with smooth climate-space blending
- Caves from two intersecting ridged 3D noise fields, plus deeper cheese caverns
- Ore distribution with per-ore depth bands and vein shapes
- Trees, boulders and small ruins that are **always complete across chunk borders**
- Oceans and lakes, ice in cold climates, beaches, snow cover, grass, ferns, flowers, cacti
- Sand and gravel fall when unsupported; torches and plants pop off when their support goes
- Stateful water and lava flow, source formation, solidification and deterministic fire spread
- Palette-compressed 16³ section snapshots and 16-bit runtime block ids for long-term content growth

**Rendering**
- Visible-face chunk mesher: one geometry per render layer per chunk, never one mesh per block
- Baked ambient occlusion, seam-free sky lighting and propagated 0–15 block light across chunk borders
- Four render layers: opaque, cutout, translucent, liquid
- Custom voxel shader with a real directional shadow map, plus an automatic fallback to stock
  materials if the GPU rejects it
- Procedural sky dome with sun, moon, stars, sunrise and sunset, driven by a keyframed day cycle
- Animated water with Fresnel and an underwater fog transition
- Scrolling volumetric-looking cloud layers from one seamlessly tiling procedural texture
- GPU-animated rain with a roof check, and weather that darkens the sky and closes in the fog
- Optional FXAA, bloom, vignette and tone mapping
- Five graphics presets from Potato to Ultra, plus dynamic resolution

**Play**
- Walking, sprinting, jumping, crouching, swimming, creative flight, auto-step
- Easy, Normal, Hardcore and the special Chug Tuff difficulty, persisted per world
- Real one-life Hardcore rules: defeated worlds are locked from replay but remain exportable
- An original articulated teal-shirt block-character with modeled face, hair, clothing and boots
- Fixed-step physics, so movement is identical at 30 and 144 FPS
- DDA voxel raycasting with reach, break progress, hardness and pick-block
- Nine-slot hotbar, full inventory/equipment/offhand slots, containers and safe one-click storage sorting
- Health, hunger, saturation, air, XP, armour, shields, bows, arrows and status-effect foundations
- Crafting table, furnace, chest, crops, animal breeding, persistent mobs/items and bounded voxel navigation
- Slabs, stairs, doors, trapdoors, fences, walls, gates, panes, beds, ladders and pressure components
- Redstone wire, levers, torches, lamps, repeaters, buttons and pressure plates
- Save/load in IndexedDB storing the seed, edits, state, block entities and persistent entities; JSON import/export

**Campaign and progression**
- Playable Overworld, Nether and End dimensions with dimension-specific generation, sky and ambience
- Nether fortresses, brewing, enchanting, villages, trading, strongholds and twelve-frame End portals
- Endermen with stare, teleport, water and block-carrying behaviour; silverfish and infested stronghold blocks
- Multi-part Ender Dragon fight with crystals, healing beams, boss bar, breath, knockback and 12,000 XP reward
- Exit fountain, unique dragon egg, outer-island gateway and four-crystal dragon respawning
- End cities and ships with shulkers, persistent shulker boxes and durable elytra gliding
- Original end poem and credits, return-home flow, advancement tree, statistics and death markers

Requires **Node.js 22.17 or newer** (or Node.js 24+).

```bash
npm install
```

npm run dev

## Static hosting

The build emits relative URLs (`base: './'`), so `dist/` can be served from any static host,
including a sub-path, with no configuration.

- **GitHub Pages** — run `npm run build`, then publish `dist/`. With the default `base: './'` this
  works from `https://user.github.io/repo/` without changes. A minimal workflow:
  ```yaml
  # .github/workflows/pages.yml
  name: Deploy to Pages
  on: { push: { branches: [main] } }
  permissions: { contents: read, pages: write, id-token: write }
  jobs:
    deploy:
      runs-on: ubuntu-latest
      environment: github-pages
      steps:
        - uses: actions/checkout@v4
        - uses: actions/setup-node@v4
          with: { node-version: 20, cache: npm }
        - run: npm ci && npm run build
        - uses: actions/upload-pages-artifact@v3
          with: { path: dist }
        - uses: actions/deploy-pages@v4
  ```
- **Cloudflare Pages** — build command `npm run build`, output directory `dist`.
- **Netlify** — build command `npm run build`, publish directory `dist`.

No special headers are required. The engine deliberately avoids `SharedArrayBuffer`, so
cross-origin isolation (`COOP`/`COEP`) is **not** needed.

| Ultra | 14 chunks | on | reflective | FXAA + bloom + vignette | 1.0x, DPR cap 2.0 |

Editing any preset-controlled option switches the preset to **Custom**; nothing is silently

device memory and screen size to choose a starting preset, and tells you which one it picked.

## Performance tips

In rough order of effect:

1. **Max pixel ratio** — the biggest single lever on phones. A modern handset reports a DPR of 3,
   which is nine times the pixels of 1.0. Capping it at 1.0–1.5 costs very little sharpness.
2. **Resolution scale** and **dynamic resolution** — the UI stays sharp either way, because only the
   3D view is scaled.
3. **Render distance** — cost grows with the square of the radius.
4. **Shadows** — a whole extra scene pass. Off below High for a reason.
5. **Chunk upload budget** — lower values load the world more slowly but keep frame times flat.
6. **Bloom** — the most expensive post pass; FXAA is nearly free by comparison.
7. **Particles and weather quality** — set either to Off to remove them entirely, not just reduce
   them.

Targets: ~30 FPS on a weak phone at Potato/Low, 45–60 on a mid-range phone, 60+ on an ordinary
desktop at Medium/High.

## Save system

Terrain is a pure function of the seed, so the world itself is never written to disk. A save holds:

- world name, seed, format version, timestamps and play time
- player position/rotation, inventory, equipment, survival stats, effects, mode and time of day
- **only the blocks you changed**, stored as validated voxel-index plus 16-bit block/state words
- block entities such as chests/furnaces and persistent living/dropped-item entities

An untouched world therefore costs a few hundred bytes. Autosave runs on a configurable interval
(default 45 s), on pause and on page hide, and each save is written in **one IndexedDB transaction**
— if it fails for any reason, including a quota error, the transaction aborts and the previous save
is left completely intact. Saves can be exported and imported as JSON; import always creates a new
world rather than overwriting one.

## Architecture

### Frame structure

```
fixedUpdate(1/60) x0..5   physics, world cascades
update(dt)                input, camera, streaming, interaction, UI
render(dt)                draw
```

Look input is applied in `update` at full frame rate so aiming is smooth; movement is consumed by
`fixedUpdate` so it cannot depend on frame rate. Frame deltas above 250 ms are discarded rather than
simulated, so returning from a hidden tab never teleports the player.

### Chunk streaming

Two priority queues, ordered by distance from the player minus how closely the chunk lies along the
camera's forward direction, so the world fills in ahead of you first.

The **generation radius is one chunk larger than the mesh radius**. Correct face culling and ambient
occlusion at a chunk border need the neighbouring voxels, so a chunk is only meshed once all eight
of its neighbours have data — otherwise the frontier chunk would be meshed against emptiness and
show a wall of faces that had to be rebuilt a moment later.

Every stage is bounded: generation by worker capacity, meshing by how many padded volumes we will
build per frame, GPU upload by the `uploadBudget` setting. Flying quickly re-scans from the new
position and *prunes* obsolete queue entries instead of draining them.

### Worker protocol and buffer ownership

Workers own a generator and a mesher and answer requests; all scheduling stays on the main thread,
so cancelling obsolete work is just ignoring a reply. Every reply carries a job id and the chunk's
version counter, and is applied only if the chunk still exists and still wants it.

Typed arrays are transferred, never copied. `generate` transfers voxel data out; `mesh` transfers a
padded 18x130x18 volume *in* and the same buffer back out under `recycled`, so the 42 KB allocation
is pooled and reused rather than churned.

### Meshing and lighting

The mesher receives the chunk plus one block of padding on every side — exactly what face culling
(6 neighbours) and ambient occlusion (8 corner neighbours) need for border voxels, in a single
transferable buffer.

Sky light is computed **per column**: light starts at 15 above the world and is reduced by each
block's attenuation on the way down. Leaves and water attenuate partially, so canopies are dappled
and water dims with depth, while rock cuts the sky off entirely. Emissive blocks feed a separate
0–15 voxel flood over a 3×3 chunk neighbourhood; the centre chunk extracts that field for meshing,
so torches, lava, fire and powered lamps turn corners and cross chunk borders without seams.

Ambient occlusion is the classic three-neighbour corner test, and the quad's triangle diagonal is
chosen from the AO values so corner shadows read as gradients rather than creases.

### Collision

Movement is applied one axis at a time — Y, then X, then Z — with each axis resolved before the next
is attempted. That is what produces sliding: walking diagonally into a wall stops the blocked axis
while the free axis keeps moving. Y goes first so landing is decided before horizontal movement,
making `onGround` reliable on the same frame you touch down. Movements longer than 0.4 blocks are
sub-stepped, so tunnelling is impossible by construction rather than by luck.

### Resource ownership

`ResourceManager` distinguishes **shared** resources (the atlas, the four layer materials) from
**transient** ones (chunk geometry). Unloading a chunk disposes its geometry and never its material;
`Game.destroy()` disposes everything and leaves the page in a state where a fresh `Game` could be
constructed.

## Known limitations

This package delivers a broad Phase 1–5-inspired campaign, but it does not claim that every roadmap
line or commercial-edition mechanic is complete. Automated deterministic, build and Chromium/WebGL
gates cover the shipped behavior. Important remaining boundaries include:
- **Vertical runtime streaming still uses full 128-block chunk columns.** A validated palette-based
  16³ section codec and chunk-section snapshots now exist, but the renderer/streamer has not yet
  been fully migrated to independently loaded vertical sections or configurable world height.
- **Mob navigation is bounded local voxel A*.** It now searches 2000 nodes across a 40-block
  radius with diagonal movement (octile heuristic, corner-clipping guarded), doors and ladders,
  but does not yet include hierarchical long-distance navigation or specialised aquatic/flying
  navigation graphs.
- **Exact edition parity is not claimed.** Redstone, fluids, combat timings, trading and mob
  behaviour are deterministic game systems, not byte-for-byte replicas of a particular edition.
- **Fluids and fire are deterministic gameplay simulations, not exact edition parity.** They support
  levels, falling columns, source formation, water/lava reactions, ignition, spread and burnout;
  edge-case flow search, waterlogging and every fire-spread rule still need compatibility work.
- **No real-time water reflections or cascaded shadow maps.** The engine favours a stable, scalable
  baseline and keeps the expensive effects optional.
- **Real-device performance varies.** Responsive layout and Potato-to-Ultra profiles are tested, but
  weak phones, unusual drivers and very long survival sessions still benefit from device-specific tuning.
- **The game uses original procedural art/audio and is unofficial.** Mechanics can be inspired by
  block-survival games, but Mojang/Microsoft assets, source code and branding are not included.

See `V9-IMPROVEMENTS.md` for the shipped Version 9 changes and verification record.

## Troubleshooting

**Black screen, or "The engine could not start"**
WebGL is unavailable. Enable hardware acceleration in your browser settings, update your graphics
driver, and close other heavy tabs. The error screen shows the underlying message.

**"Your GPU rejected the custom voxel shader"**
The engine detected this and switched to stock materials automatically. The world is fully playable;
you lose baked ambient occlusion and the custom fog. Please open an issue with your GPU string from
the debug overlay (`F3`).

**Very low frame rate**
Open Settings and lower **Max pixel ratio** first, then **Render distance**. Check the debug overlay
(`F3`): if `draws` is high but `fps` is low you are GPU-bound (lower the resolution), and if the
chunk queues are long you are CPU-bound (lower the render distance or the upload budget).

**Worlds disappear after a reload**
Browser storage is blocked — common in private browsing. The main menu says so on load. The game
still works, in memory only.

**Stuck inside a block**
Should not happen, but jump: the collision resolver searches upwards for free space on every
teleport and world load. If it persists, note the coordinates and open an issue.

**Touch controls not responding after switching apps**
Should not happen — `pointercancel` is treated as a release everywhere. If a control sticks, tap it
once to clear it and please report it.

## Extending the engine

### Add a block

1. Append tile names to `TILE_NAMES` and painters to `TILE_PAINTERS`; never reorder existing atlas
   names because saves and generated art assume stable contracts.
2. Append an ID to `Block`, then add its `BLOCK_DEFINITIONS` entry. IDs are 16-bit at runtime; never
   reuse an existing value for another block.
3. For non-cubes, add a shared model in `src/world/BlockModels.js`. Rendering, collision and
   raycasting must consume the same shape rather than three independent special cases.
4. For simulation, define state helpers in `BlockState.js` and register hooks through
   `BlockBehaviorRegistry` from a pack under `src/world/behaviors/`.
5. Add the block item, recipe/creative grouping, deterministic tests, persistence coverage and a
   browser interaction check when the feature is visible or interactive.

`BlockRegistry` validates IDs, textures and definitions at module load. Run `npm run audit` and
`npm run selftest` before committing a registry change.

### Add a biome

1. Add an id to the `Biome` enum in `src/world/BiomeGenerator.js`.
2. Add a definition to `BIOMES` with its position in climate space (`temperature`, `moisture`) and
   its height profile (`baseHeight`, `amplitude`, `roughness`), surface blocks and vegetation
   densities.

Blending is automatic: height is the inverse-square-weighted blend of every biome's profile, so a
new entry morphs smoothly into its neighbours. Keep climate-space positions spread out, or the new
biome will crowd out its neighbours.

### Add a shader

Put the GLSL in `src/rendering/shaders/` and import it with Vite's `?raw` suffix in
`src/rendering/ShaderManager.js`. Validate the material with `shaderManager.validateMaterial()`
before trusting it, and give it a fallback.

Two rules for fragment shaders here: Three's own prefix already defines the colour-space and
tone-mapping helpers, so include only the *call-site* chunks (`<tonemapping_fragment>`,
`<colorspace_fragment>`) and never their `_pars_` counterparts. And validation must **render**, not
just compile — Three defers shader error checking to a program's first use.

### Modify terrain generation

`src/world/TerrainGenerator.js` is the pipeline; each stage is a separate module
(`BiomeGenerator`, `CaveGenerator`, `OreGenerator`, `StructureGenerator`). Two invariants:

- Every stage must be a pure function of `(seed, worldX, worldZ)`, or chunks generated by different
  workers will disagree at their shared border.
- Features crossing a chunk border must be replayed from the neighbouring chunk's own deterministic
  roll — see the 3x3 neighbourhood pass in `StructureGenerator` — and must consume the same number
  of random values whether or not their blocks land in the chunk being generated.

Run `npm run selftest` after any change; it checks determinism, border continuity and biome
diversity directly.

### Replace the procedural assets

- **Textures**: replace the painter functions in `TILE_PAINTERS`, or load an image atlas in
  `TextureAtlas.build()` and keep the layout in `src/world/AtlasLayout.js` in sync.
- **Sounds**: replace the recipes in `src/audio/SoundRegistry.js`, or decode files into
  `AudioManager._buffers` under the same keys.
